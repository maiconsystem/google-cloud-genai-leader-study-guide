## 🔴 Multi-select — where most marks leak

1. **Plural noun in the stem** ("components", "advantages", "considerations") = more than one answer.
2. **Judge each option on its own: true or false?** Don't hunt for "the best one".
3. **Never submit one tick** unless you've rejected the other three for a reason.

## How to answer every question

- **Eliminate three, then justify one.**
- **Re-read the stem after choosing** — does your answer cover every qualifier? (*confidential, live call, multi-step, monthly, no ML expertise*)
- **Leadership exam:** people, process, governance are real answers — not just technology.
- **Distrust absolutes:** "guarantees", "ensures all", "eliminates the need".
- **Trust what the stem says already works** — the problem isn't there.
- Unsure? Flag it, pick your best guess, move on. **Never leave one blank.**

## The rules that decide questions

- **Changing facts → RAG. Changing behaviour/tone → fine-tuning.** Confidential + must cite → RAG.
- **Grounding controls facts, not tone.**
- **Function calling:** the model *requests* (structured JSON); **your code executes.**
- **Multi-step calculations → Code Interpreter.**
- Tool types: **extensions, functions, data stores, plugins.**
- Grounding data: **first-party, third-party, world.**
- Temperature low = factual/consistent · high = creative.
- Hallucination → ground it (RAG), then human review.
- Unlabelled data + find groups/anomalies → **unsupervised.** Rewards/penalties → **reinforcement.**
- Quick + small budget + no expertise → **pre-built.**
- Shared responsibility: customer owns **access controls & governance policies**; configuration is **shared**.
- Privacy → **anonymise/pseudonymise before processing** — never turn off logging.
- Security list: **SAIF, secure-by-design, IAM, Security Command Center, workload monitoring.**
